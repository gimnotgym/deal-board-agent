SKAX는 전사 MPRS에 Agent 적용을 가속화하고 있습니다. 하지만 Agent의 분석 품질은 결국 데이터의 질에서 시작됩니다. Value chain의 출발점인 사업기회 데이터가 빈약하면, 뒤에 올 모든 Agent의 판단 품질이 함께 떨어집니다.

①
입력하기 싫어하는 영업대표 → 에이전트와 대화하는 영업대표
기존 CRM은 입력칸이 너무 많고, 정작 중요한 맥락 데이터는 비어 있습니다. 진짜 딜의 맥락은 개인의 기억과 로컬 PC에 흩어집니다.
영업대표 인터뷰에서 발견한 인사이트 — "영업대표는 대화를 좋아한다!" 영업대표와 대화를 이끌며 필요한 정보를 자연스럽게 채우는 에이전트를 만들었습니다.
②
좋은 딜을 판단하는 기준의 부재 → 사업기회 Scoring 정량화
수주 가능성 판단이 담당자 개인의 경험과 직관에 의존합니다. 영업 품질에 대한 개인의 편차도, 의사결정의 기준도 달라집니다.
글로벌 B2B에서 통용되는 프레임워크(MEDDPICC)를 활용해 사업기회를 0~100점으로 Scoring 합니다.
③
보고 중심의 의사결정 구조 → 시스템 기반 의사결정
Weekly, Monthly, Risk검토, 입찰결정… 다양한 목적의 정기보고를 위해 만들어지는 보고서들. 정기 회의체 중심의 의사결정이 영업 속도를 늦춥니다.
영업정보의 시작도, 끝도 시스템에서 실시간으로 이뤄지게 합니다.

AI 적용 설계에 대한 질문들

왜 여기에 AI를 쓰고, 어떻게 제어하며, 무엇이 남았는가

01
AI를 적용할 영역을 선정한 기준은?
기존 영업 시스템이 할 수 없었던 자연어 처리 영역에 집중
어떤 기준으로 LLM을 적용할 유스케이스를 골랐나요?

기존 CRM(Salesforce, SAP)이 처리하지 못하는 영역을 먼저 정의했습니다. 기존 시스템은 정형화된 필드 입력만 처리할 수 있어, 영업대표가 미팅 후 남기는 자유 형식의 메모나 통화 기록에서 영업적 맥락을 자동으로 읽어내는 것이 불가능했습니다.

이를 출발점으로, "자연어로 입력된 정보에서 구조화된 판단을 이끌어내야 하는 곳"을 LLM 적용 유스케이스로 설계했습니다. 도출된 기능은 아래 3가지입니다.

🤖 Agent 1 — MEDDPICC 자동 분석
영업대표가 입력한 자유 형식 메모를 LLM이 읽고, MEDDPICC 8개 항목 각각에 대해 0~3점으로 자동 평가합니다. "오늘 CFO를 만났는데 예산 3억이 확정됐고 경쟁사 A도 들어왔다"는 한 문장에서 M(예산확인 +2점)·CO(경쟁사 식별 +1점)를 자동 추출합니다.
🤖 Agent 2 — AI 코칭 노트 생성
딜의 전체 컨텍스트(고객사, Stage, MEDDPICC 현황, 수주확도, 입찰일 등)를 LLM에 전달하면, 가장 취약한 MEDDPICC 항목을 중심으로 맞춤 Next Action을 제안합니다. 단순 템플릿이 아니라 딜마다 다른 코칭이 나옵니다.
🤖 Agent 3 — 임원 브리핑 챗
사업부문장이 "이번 분기 Gap이 얼마야?", "수주 위험 딜 어디야?" 같은 자연어 질문을 입력하면, LLM이 실시간 파이프라인 데이터를 기반으로 목표 달성 추정, Gap 후보 Lead, 단계별 주요 딜을 즉시 서술합니다.
02
AI를 적용하지 않을 영역을 선정한 기준은?
결과가 명확하고 설명 가능해야 하는 곳은 Human이 룰을 직접 정의
어떤 기능은 LLM 대신 룰베이스로 구현했고, 왜 그 선택을 했나요?

LLM은 같은 입력에도 매번 다른 결과를 낼 수 있습니다. 결과가 항상 동일해야 하고, 그 근거를 사람이 명확히 설명할 수 있어야 하는 곳에는 로직을 상세히 정의한 룰베이스를 적용했습니다.

⚙️ 5-Factor 딜 스코어 (100점)
딜 스코어는 영업 코칭·자원 배분의 근거가 되므로 공식을 완전히 공개했습니다. SF(전략적합도 20점) = 중점사업 10 + 중점고객 6 + AX사업 4 / DQ(딜품질 30점) = MEDDPICC 가중합÷36×30 / AC(활동성 15점) = 최근 30일 업데이트 횟수 5단계 / CH(고객이력 20점) = 계약건수(최대 15) + 규모보정(최대 5) / RR(담당자 승률 15점) = 구간별 기본점수 + 표본 신뢰도 보정. "왜 내 딜 점수가 낮지?"라는 질문에 항목별로 명확히 답할 수 있습니다.
⚙️ Stage 체류 위험 감지
각 영업 단계(Lead → Identified → Qualified → Negotiated)별로 관리자가 직접 기준일을 설정합니다. 해당 기준일을 초과하면 자동으로 경보가 발생합니다. "AI가 위험하다고 판단"이 아니라, "사람이 정한 기준을 넘겼다"는 명확한 근거입니다.
⚙️ 목표 달성 추정 · Gap 계산
목표 달성 추정 = Σ(수주목표액 × 수주확도) ÷ 목표액 × 100. Gap = 목표액 − 계약완료액. 수식이 완전히 공개되어 있어 임원이 숫자의 근거를 즉시 추적할 수 있습니다.
03
생성형 AI의 제약을 어떻게 극복하려고 했는가?
할루시네이션·확률적 불일관성을 프롬프팅·피드백 루프·HITL로 제어
LLM은 같은 메모를 넣어도 매번 다른 결과가 나오지 않나요?

생성형 AI는 두 가지 근본적인 한계가 있습니다. 할루시네이션(없는 사실을 그럴듯하게 만들어냄)과 확률 기반 출력(같은 입력에도 매번 다른 결과). 이를 극복하기 위해 3계층 설계를 적용했습니다.

① 프롬프팅 설계 — 출력 형식을 강제한다
"자유롭게 분석해줘"가 아니라, 반드시 이 JSON 형식으로만 답하라고 지시합니다.
{"M": 2, "E": 1, "DC": 0, "DP": 1, "I": 2, "C": 1, "PP": 0, "CO": 1}
각 항목은 0~3 정수만 허용하며, 형식을 벗어난 응답은 서버에서 파싱 오류로 차단하고 자동 재시도합니다. LLM이 "예산이 확정된 것 같습니다"라고 서술하는 대신, 반드시 숫자로만 답하게 만드는 구조입니다.
② 피드백 루프 — 도메인 전문가가 LLM을 지속적으로 교육한다
관리자 페이지에서 영업 전문가가 "이 메모를 입력하면 이 결과가 정답"이라는 예시(Few-shot)를 직접 등록합니다. 이 예시가 매번 프롬프트 앞에 자동으로 붙어, LLM이 SK 영업 맥락에 맞게 판단하도록 유도합니다.

영업대표가 AI 결과를 수정하면 그 수정 내용이 충돌 로그에 자동 기록되고, 관리자가 이를 새 정답 예시로 등록해 시스템이 점점 정확해지는 피드백 루프가 형성됩니다. 예시 품질이 곧 분석 품질입니다.
③ HITL 설계 — AI가 틀려도 사람이 최종 확정한다
AI 분석 결과는 절대 자동 확정되지 않습니다. 항상 "AI 제안 초안"으로 표시되고, 영업대표가 직접 검토·수정·확정합니다. AI가 틀린 판단을 해도 데이터에 반영되기 전에 사람이 필터링하는 구조입니다.

추가 안전장치로, LLM이 영향을 미치는 부분은 5-Factor 딜 스코어 중 DQ(딜품질, 30점) 하나뿐입니다. 나머지 4개 인수(SF·AC·CH·RR)는 LLM과 완전히 무관하게 룰베이스로 계산되므로, AI 오류가 전체 스코어에 미치는 영향이 구조적으로 제한됩니다.
03
여전히 극복해야 할 잔여 과제
기술적 완성도와 조직 수용성, 두 축의 미해결 문제
입력 형식 다양화와 AI 분석 품질 검증은 어디까지 해결됐나요?

현재 MVP는 텍스트 메모 입력 한 가지만 지원합니다. 실제 영업 현장에서는 훨씬 다양한 형식으로 정보가 발생하며, 이것이 가장 큰 기술적 잔여 과제입니다.

🎙️
음성 입력 (미지원)
고객 미팅 직후 이동 중에 음성으로 기록하는 것이 가장 자연스러운 입력입니다. STT(Speech-to-Text) 연동 후 동일한 MEDDPICC 파이프라인에 흘려보내는 구조는 설계됐으나 미구현 상태입니다.
📧
이메일·메신저 자동 수집 (미지원)
영업대표가 별도 입력하지 않아도, 고객과의 이메일·Teams 메시지에서 딜 관련 내용을 자동 추출하는 것이 궁극적 목표입니다. 이를 위해선 입력 다양성만큼 노이즈 필터링과 오추출 방지 정확도가 핵심 과제가 됩니다.
✅
분석 품질의 정량 검증 (미완성)
현재는 Few-shot 예시 품질에 의존하지만, "AI 분석이 얼마나 정확한가"를 수치로 측정하는 체계가 없습니다. 전문가 정답셋(ground truth) 구축 → Precision/Recall 측정 → 프롬프트 개선의 반복 루프가 필요합니다.
시스템 기반 의사결정으로의 업무 방식 변화, 어떻게 관리할 것인가요?

기술 완성도보다 더 어려운 문제일 수 있습니다. 영업 조직은 오랜 경험과 직관을 신뢰하는 문화가 강하고, "AI가 내 딜을 점수로 매긴다"는 것에 거부감이 생길 수 있습니다.

① "AI가 평가한다"는 프레이밍을 버려야 합니다
딜 스코어는 평가 도구가 아니라 대화 도구입니다. "왜 이 딜 점수가 낮을까?"가 리더-영업대표 1:1 코칭의 출발점이 되어야 합니다. 점수로 줄 세우는 문화가 생기면 데이터가 왜곡됩니다.
② 초기 도입 단계에서는 "추천"이지 "결정"이 아님을 명확히 해야 합니다
AI 코칭 노트, 위험 경보, Gap 후보 Lead는 모두 사람의 판단을 돕는 인풋입니다. 시스템 추천을 무시하고 영업대표 직관으로 수주한 사례가 쌓일수록, 역설적으로 시스템에 대한 신뢰도가 올라갑니다. 강제하지 않는 것이 중요합니다.
③ 변화관리의 핵심은 초기 성공 사례(Quick Win)입니다
"AI가 위험 신호를 잡아서 살린 딜", "코칭 노트 덕분에 다음 미팅을 잘 준비한 사례" 같은 구체적 성공 스토리가 조직 내 확산의 가장 강력한 동력입니다. 파일럿 팀 선정과 초기 성공 사례 발굴이 기술 개발만큼 중요합니다.
